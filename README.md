# engineering-lab

시스템이 실제로 어떻게 동작하는지 파 보고 남기는 기록.

## 읽는 법

| 폴더              | 무엇인가                           | 성격                               |
| ----------------- | ---------------------------------- | ---------------------------------- |
| [`paths/`](paths) | 여러 실체를 순서대로 지나가는 흐름 | 얇다. 단계마다 몇 줄과 링크만 둔다 |
| [`nodes/`](nodes) | 실체 하나에 대한 현재의 이해       | 계속 고쳐 쓴다. 지식의 본체        |

경로 문서에서 시작해, 궁금한 단계의 노드로 들어가면 된다.

노드 문서는 같은 순서로 쓴다: **개요 → 용어 → 책임 → 구조 → 상태 → 수명주기 → 인터페이스 → 플랫폼 차이 → 미해결 질문 → 관련 문서 → 참고 문헌**. 실체에 맞지 않는 칸은 뺀다(예: 파일 형식에는 책임이 없다). 플랫폼 대신 버전이나 빌드에 따라 달라지면 그 이름으로 쓴다.

경로 문서는 **개요 → 전체 그림 → 단계 → 요약 → 빈 구간 → 참고 문헌** 순이다. 단계는 ①~④로 묶어 표로 정리하고, 자세한 내용은 노드로 넘긴다.

## 근거

- **공개 소스**: Apple의 공개 소스 코드. 해당 줄로 링크한다.
- **바이너리 분석 · LLDB 실측**: AI 도구의 도움을 받아 시뮬레이터의 바이너리와 실행 중인 프로세스를 조사해 얻은 것. 직접 다시 돌려 확인하기 전인 것도 있다.
- **외부 자료**: 제3자의 공개 코드나 공개된 기기 로그. 다른 iOS 버전이거나 Apple의 현재 구현과 같다는 보장이 없다.
- **문서**: Apple 공식 문서, 매뉴얼 페이지, 표준 문서.

확인하지 못한 것은 추측으로 채우지 않고 **미해결 질문**에 남긴다.

분석 환경은 iOS 26.1 시뮬레이터(23B86), Apple Silicon Mac, Xcode 26.1.1이다. 소스 링크는 [xnu-12377.1.9](https://github.com/apple-oss-distributions/xnu/tree/xnu-12377.1.9)와 [dyld-1378](https://github.com/apple-oss-distributions/dyld/tree/dyld-1378) 태그 기준이다. 분석에 쓴 기기의 빌드와 줄 단위로 같다는 보장은 없다.
